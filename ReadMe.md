## 3. Задание

### 3.1. Основное задание

Инициализация проекта через `npm`, настройка `package.json`. Создание Single Page Application (SPA) с разделением кода на страницы (`pages`) и независимые компоненты (`components`). Специфические требования по варианту:

* **Страницы:** Реализовать главную страницу (`/main`) со списком карточек услуг/объектов и страницу детального просмотра (`detail.html`) для отображения 3D-модели.
* **Фильтрация и управление данными:** Данные для карточек хранятся в виде массива объектов с полями `id`, `title`, `text`. Навигация к детальной странице осуществляется по клику на карточку с передачей идентификатора модели через параметры URL.
* **Компоненты:** Разработать переиспользуемые компоненты: `ProductCardComponent` (карточка товара), `HeadComponent` (шапка сайта), `LinkButtonComponent` (кнопка-ссылка).
* **Визуализация 3D:** Страница детального просмотра должна загружать и отображать 3D-модели в формате `.glb`. Реализовать возможность управления камерой (вращение, масштабирование) и быстрого переключения между предустановленными ракурсами («Спереди», «Сзади» и т.д.).
* **Требование к верстке:** Использовать Bootstrap 5 для построения адаптивной сетки карточек и базовых стилей.

### 3.2. Дополнительное задание (3D-визуализация)

Реализовать компонент для просмотра 3D-моделей с использованием библиотеки Three.js.

* **Технологии:** Сцена создается с помощью `WebGLRenderer`, добавляется освещение (`AmbientLight`, `DirectionalLight`) и вспомогательные элементы управления камерой (`OrbitControls`).
* **Загрузка моделей:** Модели загружаются динамически с помощью `GLTFLoader`. Поддерживается загрузка как одиночных моделей, так и композиций из двух объектов (например, «Машина + Дерево»).
* **Пользовательские сценарии:** На странице `detail.html` реализованы кнопки для управления камерой (приближение/отдаление) и выбора предустановленных ракурсов.
* **Передача данных:** Идентификатор отображаемой модели передается через параметр `id` в URL. Также предусмотрена поддержка загрузки моделей из буфера (параметр `user`), что позволяет расширить функционал для работы с пользовательскими данными.

## 4. Теория и реализация (Примеры из кода)

### 4.1. Компонентная архитектура и управление состоянием

**Теория:** Для обеспечения переиспользуемости и модульности кода интерфейс был разбит на независимые компоненты. Каждый компонент представлен отдельным JavaScript-классом, который отвечает за рендеринг своей HTML-разметки и навешивание обработчиков событий. Такой подход упрощает поддержку и масштабирование проекта.

Главная страница (`MainPage`) выступает в роли контейнера, который инициализирует общие компоненты (`HeadComponent`) и динамически генерирует список дочерних компонентов на основе данных (`ProductCardComponent`). Это позволяет легко добавлять, удалять или изменять карточки без вмешательства в структуру других частей приложения.

**Пример из кода (Компонент карточки):**
``` javascript
    // components/card/card.js
    export class ProductCardComponent {
        constructor(parent) {
            this.parent = parent;
        }
    
        getHTML(data) {
            return (`
                <div class="card" style="width: 300px;">
                    <img src="${data.src}" class="card-img-top" alt="...">
                    <div class="card-body">
                        <h5 class="card-title">${data.title}</h5>
                        <p class="card-text">${data.text}</p>
                        <button class="btn btn-primary" id="click-card-${data.id}" data-id="${data.id}">Подробнее</button>
                    </div>
                </div>
            `);
        }
    
        addListeners(data, listener) {
            document
                .getElementById(`click-card-${data.id}`)
                .addEventListener("click", listener)
        }
    
        render(data, listener) {
            const html = this.getHTML(data)
            this.parent.insertAdjacentHTML('beforeend', html)
            this.addListeners(data, listener)
        }
    }
```
Как видно из кода, компонент полностью самодостаточен: он получает данные и родительский DOM-элемент, генерирует свою разметку и самостоятельно управляет своими событиями, что является ярким примером применения компонентного подхода.

### 4.2. Интеграция Three.js и динамическая загрузка моделей

**Теория:** Для создания и управления 3D-сценой была выбрана библиотека Three.js — стандартный инструмент для реализации веб-визуализации. Процесс интеграции включал в себя несколько ключевых этапов: настройка рендерера, создание сцены с камерой и освещением, а также реализация загрузчика моделей в формате glTF (`.glb`).

Для обеспечения удобства работы пользователя со сценой были добавлены элементы управления (`OrbitControls`), позволяющие вращать, перемещать и масштабировать камеру. Кроме того, были реализованы функции для автоматического изменения размеров сцены при изменении размера окна браузера (`resizeRendererToDisplaySize`). Поддерживается загрузка как одиночных моделей, так и композиций из нескольких объектов, которые располагаются на сцене с заданным интервалом (переменная `gap`).

**Пример из кода (Инициализация сцены и загрузка модели):**
``` javascript
    // detail.js
    function renderModel() {
        const canvas = document.getElementById('viewer-canvas');
        const renderer = new THREE.WebGLRenderer({ canvas, antialias: true });
        const scene = new THREE.Scene();
        scene.background = new THREE.Color(0xe6ebf5);
        const camera = new THREE.PerspectiveCamera(60, canvas.clientWidth / canvas.clientHeight, 0.1, 1000);

        const controls = new OrbitControls(camera, renderer.domElement);
        controls.enableDamping = true;
        controls.enableZoom = true;
        controls.target.set(0, 1, 0);
        
        scene.add(new THREE.AmbientLight(0xffffff, 0.7));
        const dirLight = new THREE.DirectionalLight(0xffffff, 0.7);
        dirLight.position.set(4, 10, 8);
        scene.add(dirLight);
        
        const loader = new GLTFLoader();
        // ... логика загрузки модели
    }
```
Этот фрагмент демонстрирует основные этапы создания 3D-сцены: настройку рендерера, камеры, освещения и элементов управления.

### 4.3. Маршрутизация с передачей параметров

**Теория:** Навигация между главной страницей и страницей детального просмотра модели реализована с помощью передачи параметров через URL. Такой подход является классическим для SPA и позволяет сделать приложение доступным для индексации, а также дает возможность пользователям делиться ссылками на конкретную 3D-модель.

При клике на карточку на главной странице формируется ссылка на `detail.html` с добавлением параметра `id`, соответствующего выбранной модели. На странице `detail.js` этот параметр извлекается из строки запроса с помощью `URLSearchParams`, после чего происходит поиск нужной модели в заранее определенном массиве `PRESETS`. Помимо идентификатора, в URL также может быть передан параметр `user`, который указывает на необходимость загрузки модели из пользовательского буфера, что открывает возможности для будущего расширения функционала.

**Пример из кода (Обработка параметров URL):**
``` javascript

    const params = new URLSearchParams(window.location.search);
    const id = params.get('id');

        getModelByIdFromDB(userId).then(userModel => {
            // ... логика загрузки пользовательской модели
        });
    }
```
Этот фрагмент кода показывает, как приложение анализирует URL и на его основе определяет, какую именно модель необходимо отобразить, демонстрируя базовую, но эффективную систему маршрутизации.
