## 4. Теория и реализация (Примеры из кода)

### 4.1. Инкапсуляция AJAX‑запросов и маршрутов

**Теория:** Для обеспечения чистоты архитектуры логика работы с сетью вынесена в отдельные модули `ajax.js` и `backupTypeUrls.js`. Класс `Ajax` является универсальной оберткой над встроенным браузерным объектом `XMLHttpRequest`. Он скрывает низкоуровневую логику установки заголовков, сериализации JSON и отслеживания состояния запроса (`readyState === 4`). Обработка ответа происходит асинхронно через функции обратного вызова (callbacks).

**Пример из кода (Реализация POST‑запроса):**
``` js
    // modules/ajax.js
    class Ajax {
        post(url, data, callback) {
            const xhr = new XMLHttpRequest();
            xhr.open('POST', url);
            xhr.setRequestHeader('Content-Type', 'application/json');
            xhr.send(JSON.stringify(data));
            xhr.onreadystatechange = () => {
                if (xhr.readyState === 4) {
                    this._handleResponse(xhr, callback);
                }
            };
        }
        // ... приватный метод _handleResponse для парсинга JSON
    }
    export const ajax = new Ajax();
```
**Пример из кода (Маршруты для работы с типами резервного копирования):**
``` js
    // modules/backupTypeUrls.js
    class BackupTypeUrls {
        constructor() {
            this.baseUrl = 'http://localhost:3000';
        }
        getBackupTypes() {
            return `${this.baseUrl}/backupTypes`;
        }
        getBackupTypeById(id) {
            return `${this.baseUrl}/backupTypes/${id}`;
        }
        getBackupTypeByTitle(title) {
            return `${this.baseUrl}/backupTypes?title=${title}`;
        }
        // ... методы для создания, удаления, обновления
    }
    export const backupTypeUrls = new BackupTypeUrls();
```
Модуль `backupTypeUrls` централизует построение URL‑адресов, что облегчает поддержку проекта при изменении структуры API.

### 4.2. Решение проблемы CORS на стороне сервера

**Теория:** Поскольку клиент и сервер находятся на разных портах (например, клиент на порту 5500, сервер на порту 3000), браузер блокирует запросы из‑за политики одинакового источника (Same‑Origin Policy). Проблема решена архитектурно верно — путем добавления глобального Middleware в Express.js на бэкенде. Сервер явно разрешает кросс‑доменные запросы и корректно отвечает на предварительные запросы‑разведчики (`OPTIONS`, preflight), необходимые для сложных методов (`POST`, `PATCH`).

**Пример из кода (Настройка CORS на бэкенде):**
``` js
    // backend: index.js
    app.use((req, res, next) => {
        res.header('Access-Control-Allow-Origin', '*');
        res.header('Access-Control-Allow-Methods', 'GET, POST, PATCH, DELETE, OPTIONS');
        res.header('Access-Control-Allow-Headers', 'Content-Type');
        // Моментальный ответ на preflight‑запрос браузера
        if (req.method === 'OPTIONS') {
            return res.sendStatus(200);
        }
        next();
    });
```
### 4.3. Фильтрация данных на главной странице (GET с параметрами)

**Теория:** На главной странице реализована возможность фильтрации списка типов резервного копирования по названию. При наличии параметра `title` в URL формируется запрос с соответствующим query‑параметром, что позволяет серверу вернуть только релевантные записи. Кроме того, компонент `limiter` ограничивает количество выводимых элементов на странице.

**Пример из кода (Загрузка и отображение списка с фильтрацией):**
``` js
    // pages/main/main_page.js
    import {ajax} from "../../modules/ajax.js";
    import {backupTypeUrls} from "../../modules/backupTypeUrls.js";

    export class MainPage {
        getData() {
            const params = new URLSearchParams(window.location.search);
            if (params.get('title')) {
                ajax.get(backupTypeUrls.getBackupTypeByTitle(params.get('title')), (data) => {
                    this.renderData(data);
                });
            } else {
                ajax.get(backupTypeUrls.getBackupTypes(), (data) => {
                    this.renderData(data);
                });
            }
        }

        renderData(items) {
            this.pageRoot.innerHTML = "";
            items = (this.limit === 0) ? items : items.slice(0, this.limit);
            items.forEach((item) => {
                const productCard = new ProductCardComponent(this.pageRoot);
                productCard.render(item, this.clickCard.bind(this));
            });
        }
        // ...
    }
```
При клике на карточку вызывается переход на страницу детального просмотра с передачей идентификатора в URL:
``` js
    clickCard(e) {
        const cardId = e.target.dataset.id;
        const productPage = new ProductPage(this.parent, cardId);
        productPage.render();
    }
```
