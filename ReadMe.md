## 4. Теория и реализация (Примеры из кода)

### 4.1. Современные сетевые запросы (Fetch API и Promises)

**Теория:** В отличие от `XMLHttpRequest`, который опирается на события изменения состояния и передачу функций обратного вызова (callbacks), современный `fetch` возвращает объект `Promise` (обещание). Использование синтаксического сахара `async/await` позволяет писать асинхронный код линейно, «приостанавливая» выполнение функции до тех пор, пока сервер не пришлет ответ, что избавляет код от излишней вложенности («callback hell»).

**Пример из кода (Реализация GET-запроса):**
``` js
    // modules/ajax.js
    class Ajax {
        async get(url) {
            try {
                // Ожидание выполнения HTTP-запроса
                const response = await fetch(url);
                // Ожидание парсинга тела ответа в JSON
                const data = response.ok ? await response.json() : null;
                
                if (!response.ok) {
                    throw new Error(`HTTP error! status: ${response.status}`);
                }
                
                return data;
            } catch (error) {
                console.error('Ошибка при выполнении GET-запроса:', error);
                return null;
            }
        }
    
        async post(url, data) {
            try {
                const response = await fetch(url, {
                    method: 'POST',
                    headers: { 'Content-Type': 'application/json' },
                    body: JSON.stringify(data)
                });
                
                const responseData = response.ok ? await response.json() : null;
                
                if (!response.ok) {
                    throw new Error(`HTTP error! status: ${response.status}`);
                }
                
                return responseData;
            } catch (error) {
                console.error('Ошибка при выполнении POST-запроса:', error);
                return null;
            }
        }
    }
    
    export const ajax = new Ajax();
```
Как видно из кода, вся логика обработки ответа больше не требует ручной проверки `readyState` или парсинга `responseText`. Промис управляет состоянием запроса, а `async/await` делает код простым и понятным.

### 4.2. Переход на async/await в бизнес-логике

**Теория:** При работе с динамическими данными важно правильно обрабатывать асинхронные вызовы. Синтаксис `async/await` идеально подходит для последовательных операций, когда, например, сначала нужно получить список доступных моделей, а затем, по выбору пользователя, загрузить  модель. Это позволяет избежать вложенных вызовов `then()` и сделать код более читаемым.

**Пример из кода (Асинхронная загрузка данных для страницы):**
``` js
    // pages/main/main_page.js
    export class MainPage {
        async render() {
            const container = document.getElementById('root');
            // Асинхронная загрузка списка моделей с сервера
            const modelsData = await this.loadModels();
            
            if (modelsData) {
                modelsData.forEach(model => {
                    const card = new ProductCardComponent(container);
                    card.render(model, (event) => {
                        this.onCardClick(event, model.id);
                    });
                });
            } else {
                container.innerHTML = '<p>Ошибка загрузки данных</p>';
            }
        }
    
        async loadModels() {
            // Используем современный fetch вместо XMLHttpRequest
            const data = await ajax.get('/api/models');
            return data;
        }
    
        async onCardClick(event, id) {
            // При клике на карточку сразу переходим к детальной загрузке
            window.location.href = `/detail.html?id=${id}`;
        }
    }
```
### 4.3. Сборка фронтенда с помощью Vite

**Теория:** Для объединения всех модулей приложения (компонентов, страниц, утилит) в единый оптимизированный файл используется бандлер Vite. Он позволяет транспилировать современный JavaScript (ES6+) в код, понятный старым браузерам, минифицирует итоговые файлы для уменьшения их размера и автоматически подставляет актуальные пути к ресурсам. Это также решает проблему CORS, так как клиентская и серверная части обслуживаются с одного домена.

**Пример из кода (Конфигурация Vite):**
``` js
    // vite.config.js
    import { defineConfig } from 'vite';
    import path from 'path';
    
    export default defineConfig({
        root: path.resolve(__dirname, 'src'),
        build: {
            outDir: path.resolve(__dirname, 'public'),
            emptyOutDir: true,
            rollupOptions: {
                input: {
                    main: path.resolve(__dirname, 'src/index.html'),
                    detail: path.resolve(__dirname, 'src/detail.html')
                }
            }
        },
        server: {
            port: 3000,
            proxy: {
                '/api': 'http://localhost:8080'
            }
        }
    });
```
После выполнения команды `npm run build` все исходные файлы из папки `src` собираются в директорию `public`, которая затем подключается к серверу на Express.js. Клиентские запросы к API больше не требуют дополнительных заголовков CORS, так как они отправляются на тот же самый хост и порт, с которого была загружена страница.
